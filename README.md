# Car Database

A personal encyclopedia of interesting cars. React + Vite, no backend —
**all car data comes from `Car Database.xlsx`** at the repo root, and photos
are plain files in folders. See [VISION.md](VISION.md) for the project vision.

## How updates work

Every push to `main` triggers a GitHub Action that converts the spreadsheet
to JSON, builds the site, and deploys it to GitHub Pages. So:

- **Update car data** → replace `Car Database.xlsx` (locally + push, or via
  GitHub web: open the file → ⋯ → *Upload files* to the repo root with the
  same name). The site rebuilds itself in ~2 minutes.
- **Add photos** → drop image files into `public/images/<brand>/<car-slug>/`
  (see below). No JSON editing needed — the build scans the folders.

## Run it locally

```
npm install
npm run dev        # converts the spreadsheet, then serves on localhost:5173
npm run build      # static site in dist/
```

## The spreadsheet

One row per car. Required columns: `Manufacturer`, `Model`, `Year` — plus the
spec/market/story columns (see existing rows). Rules:

- `Manufacturer` must match a brand name in `public/data/brands.json`
  (39 marques are themed there today — run `npm run data` and read the log
  to see the full list). Rows for a manufacturer not listed there are
  skipped with a warning; add a brand entry (accent color, family accents,
  display font, hero text) to bring a new marque online, plus its font to
  the Google Fonts link in `index.html` if it needs one.
- The car's URL slug is derived from `Model` ("Zonda C12 S" → `zonda-c12-s`).
  Renaming a model changes its slug — rename its image folder to match.
- Spec cells can be numbers or strings ("~2,400 (est.)", "Not published");
  the app displays strings as-is and parses numbers out of them for
  sorting and card stats.

## Adding photos

Two layouts work — use whichever is less effort. A car's slug is the last part
of its URL (`#/pagani/zonda-f` → `zonda-f`).

**Flat (best for bulk uploads).** Name each file after the car's slug and drop
them all in the brand folder — one folder for the entire brand, so a whole
batch goes up in a single drag-and-drop:

```
public/images/koenigsegg/agera-rs.jpg        ← cover
public/images/koenigsegg/agera-rs-2.jpg      ← second photo
public/images/koenigsegg/jesko.jpg
public/images/koenigsegg/credits.json        ← one credits file per brand
```

**Nested (good when one car has many photos).** A folder per car, numbered:

```
public/images/pagani/zonda-f/1.jpg           ← cover
public/images/pagani/zonda-f/2.jpg
public/images/pagani/zonda-f/credits.json
```

Either way, `credits.json` maps a filename to its credit string:

```json
{ "agera-rs.jpg": "Photo: Name, CC BY-SA 4.0, Wikimedia Commons" }
```

**Upload photos at whatever quality you like — the build handles the rest.**
Card grids (brand pages, home page, the gallery strip) are served a generated
560px WebP cover from `public/thumbs/`, which is ~93% smaller, while a car's
own page shows your original file untouched. `public/thumbs/` is generated and
gitignored; `public/images/` is never modified.

Files that don't match any car slug are reported in the build log and skipped.

To upload through GitHub web, go straight to the brand folder's upload page —
`github.com/<you>/car-database/upload/main/public/images/<brand>` — and drop
in the whole batch at once.

**Licensing rules** (see VISION.md): publish-safe sources only — Wikimedia
Commons, CC-filtered Flickr/Openverse, own photos, or written permission.
Every photo gets a credit string.

## Generated vs. hand-edited files

| File | Status |
|---|---|
| `Car Database.xlsx` | **source of truth** for car data — edit this |
| `public/data/brands.json` | hand-edited — brand list, themes, hero text |
| `public/data/<brand>.json` | generated by `scripts/build-data.mjs` — never edit |
| `public/images/**` | hand-managed photos + credits |

Favorites are stored in localStorage on each visitor's device.
